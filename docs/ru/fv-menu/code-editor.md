# Редактор кода в игре

Панель кода внутри редактора раскладки — для автора, который уже делает интерфейсы на веб-фреймворке. Она
**необязательна**: любую раскладку меню, HUD и загрузки можно полностью сделать без неё, ничто на
пути без кода из неё не импортирует, и поставляется она скрытой. Сначала прочитайте главу [Редактор раскладки](/ru/fv-menu/editor): это одна панель того
редактора, а не второй инструмент.

## Как включить

Два переключателя, оба по умолчанию выключены.

1. Сам редактор: `fvui/editor.json`, [Редактор раскладки](/ru/fv-menu/editor). Под замком модпака ничего из этого не появляется.
2. Панель: **Window > Code Editor**, что записывает ключ хранилища пака `ui.codeEditor`.

Когда панель выключена, `Window > Open Code Editor`, `Layout > Open in code editor`, строка контекстного
меню элемента и строка в Help скрыты. Когда она включена, а файлы заблокированы, панель открывается
только для чтения.

## Что это такое

```txt
Window > Open Code Editor
```

Закреплённая панель поверх холста: слева дерево файлов пака, сверху вкладки (не больше двенадцати
открытых, вкладка с несохранёнными правками никогда не вытесняется), редактор, под ним список проблем и рядом
необязательное превью работающего экрана.

Редактор — это `<textarea>` с подсвеченным Prism `<pre>` под ним, оба моноширинные с одной и той же
высотой строки 11 px, прокрутка синхронизирована, собственный текст textarea прозрачен над кареткой в цветах темы.
Каретка, выделение, стрелки, Home, End, Shift+стрелки и позиционирование кликом — это собственный
текстовый ввод servo, а отмена — от textarea, так что здесь ничто не реализует текстовый редактор заново. CodeMirror 6
в servo рисуется правильно, но API «пиксель → смещение в тексте» нет вообще (`caretPositionFromPoint` и
`caretRangeFromPoint` не определены, а `Range.getClientRects()` для части узла возвращает пустой список) —
поэтому он не используется; редактор стоит за одним интерфейсом компонента, так что позже его можно
заменить.

Подсветка: `.svelte` и `.vue` как разметка с вложенными script и style, `.tsx` и `.jsx`,
`.ts`, `.js`, `.css`, `.json`. Всё остальное — простой текст на той же сетке.

Нет сворачивания, виртуализации, нескольких курсоров, автодополнения и мини-карты. Файлы пака
маленькие, а две функции, которым нужна сломанная геометрия `Range`, — как раз те, что
пропущены.

## Клавиши

Сочетания Ctrl+буква доходят до страницы напрямую, и те же строки приходят ещё и событием `editor.key` —
это путь совместимости из главы [Редактор раскладки](/ru/fv-menu/editor).

| клавиши | что делают |
|---|---|
| Ctrl+S | скомпилировать, записать, перезагрузить |
| Ctrl+F | поиск и замена, переход к строке |
| Ctrl+G | переход к строке |
| Ctrl+D | дублировать строку или выделение |
| Ctrl+U | вырезать строку |
| Alt+Up / Alt+Down | переместить строку |
| Tab / Shift+Tab | увеличить, уменьшить отступ |
| Ctrl+C / Ctrl+X / Ctrl+V | копировать, вырезать, вставить |
| Ctrl+W | закрыть вкладку |
| Ctrl+Tab | следующая вкладка |
| F6 | перезагрузить пак |

В servo нет ни `navigator.clipboard`, ни `document.execCommand`, поэтому копирование и вставка идут через
доверенные действия `editor.clipboard.set` и `editor.clipboard.get` и доходят до настоящего буфера обмена ОС.
Событий композиции тоже нет, так что **IME нет**: текст CJK набирается вне игры
и вставляется.

## Линтер ограничений

Каждая строка проверяется по таблице причуд servo из главы [Матрица поддержки Servo](/ru/fv-ui/servo), по языковым секциям
файла, и на полях рядом с ней стоит точка: красная для **error** (ничего не рисуется или вызов
отклоняется), жёлтая для **warn** (рисуется иначе). Ни то ни другое не мешает сохранению. Каждая строка называет
id правила и раздел главы [Матрица поддержки Servo](/ru/fv-ui/servo), откуда оно взято.

Та же таблица работает и без игры, так что пак, собранный вне игры, получает те же строки:

```sh
node tools/check-quirks.mjs src/Title.svelte
node tools/check-quirks.mjs                    every pack source in the tree
node tools/check-quirks.mjs --table            the chapter 08 table, printed from the rules
```

## Языки

Каждый бэкенд загружается при первой компиляции своего языка и никогда при запуске.

| язык | бэкенд | цена в игре |
|---|---|---|
| `.svelte` | `svelte/compiler` | один большой чанк, прогретые компиляции за миллисекунды |
| `.vue` | `@vue/compiler-sfc`, `parse` + `compileScript({inlineTemplate: true})` + `compileStyle` | самый большой чанк |
| `.tsx`, `.ts`, `.jsx` | `sucrase`, `['typescript', 'jsx']` и автоматический runtime | самый маленький |
| `.css`, `.json` | они сами, разбираются и проверяются линтером | бесплатно |

Vue компилируется в render-функцию, так что паку нужен только runtime Vue и никогда — компилятор
шаблонов времени выполнения. `esbuild-wasm` отвергнут, а не отложен: он работает, но стоит 13.3 MB
wasm, 1.5 с холодной загрузки и около 150 MB RSS при бюджете от 250 до 500 MB.

**npm в игре нет.** Голый импорт разрешается только в `@fvui/sdk`, `@fvui/elements`, `@fvui/layout`,
`@fvui/svelte`, `svelte`, `vue`, `react` и `react-dom` — в тот единственный экземпляр каждого, который редактор уже
держит. Это правило одного экземпляра — не мелочь: две копии Vue делают `getCurrentScope()` равным null
внутри адаптера, а две копии React ломают хуки — тот же дефект, который `resolve.dedupe` чинит в
шаблонах. Всё остальное — ошибка компиляции с указанием строки и главы [Цикл разработки](/ru/fv-ui/dev-workflow).

**Проверки типов нет.** Sucrase срезает типы, а не проверяет их, а `tsc` — это около 9 MB плюс
файловая система. Запускайте `npm run check` вне игры.

## Элементы, написанные вручную

Пак может нести папку `elements/`. Один файл — один тип элемента:

```txt
fvui/packs/<id>/elements/Health.svelte      =>  the type <id>:health
fvui/packs/<id>/elements/Clock.vue          =>  the type <id>:clock
fvui/packs/<id>/elements/Gauge.tsx          =>  the type <id>:gauge
```

При сохранении панель компилирует файл, регистрирует компонент для холста и `TypeSpec` для
инспектора, палитры и валидатора. Спецификация берётся из необязательного `export const spec`;
без него панель пишет заглушку `elements/<Name>.spec.json` из пропсов, которые может прочитать (Svelte —
`$props()` и его интерфейс `Props`, Vue — `defineProps`, TSX — параметр props), каждое поле —
`{"kind": "text", "about": ""}`, пока вы его не поправите. Заглушка — обычный файл пака.

Компонент принимает базовые пропсы `{id, anchor, cls, hidden, style}` плюс собственные поля, так что
классы якорей и пользовательские свойства геометрии применяются к нему без изменений.

Когда документ размещает тип, сохранение записывает его запись в блок `types` ([Документ раскладки](/ru/fv-menu/layout-document)):

```txt
"types": {
  "mypack:clock": { "from": "./elements/Clock.vue", "component": "default", "props": ["format"] }
}
```

После этого `fvui-codegen` импортирует файл напрямую, так что сгенерированный пак не зависит ни от панели, ни от
плагина. Элемент на Vue или React идёт через один адаптер монтирования, `Foreign` из `@fvui/elements`, который
импортируют и холст, и сгенерированный пак, — это и делает превью равным тому, что
работает в игре. Сгенерированные `package.json` и `vite.config.ts` сами дополняются зависимостью фреймворка, его плагином
vite и записью `resolve.dedupe`.

## Горячая перезагрузка

Сохранение — это компиляция, затем `editor.pack.write`, затем `editor.preview.reload` на виде, показывающем
экран, затем превью нового поколения. Ошибка компиляции оставляет смонтированным последний рабочий модуль
и помечает вкладку, так что превью никогда не пустеет, пока вы печатаете.

| что правили | что перезагружается |
|---|---|
| `elements/<Name>.*` | перемонтируется каждый элемент этого типа |
| файл экрана | перемонтируется этот экран |
| `styles.css`, какой-либо `.layout.css` | таблица стилей подменяется, ничего не перемонтируется |
| `fvui.pack.json`, `theme.css` | читаются при регистрации хоста: пак перезагружает F6 |

Правка, сделанная вне игры, подхватывается опросом mtime из главы [Редактор раскладки](/ru/fv-menu/editor), и панель об этом сообщает. Отклонённая
запись показывает `code` и `message` моста.

## Проблемы

Один список под редактором: ошибки компиляции на их строках, строки линтера и ошибки времени выполнения, о которых
консоль вида сообщила, пока был смонтирован компонент пака. Source map на странице нет, поэтому
строка времени выполнения сопоставляется обратно через таблицу «сгенерированная строка → исходная строка», которую хранит каждая компиляция,
а строка внутри шаблона приблизительна.

## Новые файлы и сниппеты

**new** предлагает шаблон для каждого фреймворка (элемент, простой модуль, таблица стилей, заглушка спецификации), повторяющий
`templates/svelte`, `templates/vue` и `templates/react`, а строка сниппетов вставляет подписку на
тему, вызов действия, класс якоря, токен темы или блок `@keyframes` с
правилом `calc(<n> * var(--u))`, которое нужно работающей анимации.

## Когда перестать ей пользоваться

Панель — для правки на несколько минут, а не для создания пака с нуля. Когда перерастёте её, переходите на
путь из главы [Цикл разработки](/ru/fv-ui/dev-workflow): `templates/<framework>` вне игры с Vite, `svelte-check` или `vue-tsc`
и F6.
