# Быстрый старт

В `templates/` лежат четыре заготовки, по одной на стек. Каждая — полный UI-пак: титульный экран,
страница загрузки и скин экрана. Результат сборки `dist/` — это и есть папка пака, вокруг неё
ничего собирать не нужно.

| шаблон | стек | сборка | размер страницы |
|---|---|---|---|
| `templates/vue` | Vue 3 с `@fvui/vue` | Vite | 73 kB |
| `templates/svelte` | Svelte 5 с `@fvui/svelte` | Vite | 48 kB |
| `templates/react` | React 19 с `@fvui/react` | Vite | 232 kB |
| `templates/vanilla` | ES-модули с `@fvui/sdk` | скрипт копирования | 17 kB |

Ничего из этого не обязательно. Самый маленький полный пак — `packs/example/`: манифест, один
HTML-файл и тема из четырёх строк, вообще без npm. Если ваш пак — один экран, начните с него.
Если целое меню — с шаблона.

## 1. Создать

```sh
cp -r templates/vue ../my-pack
cd ../my-pack && npm install
```

Затем поменяйте `id`, `name`, `authors` и `description` в `pack/fvui.pack.json`. Идентификатор
должен подходить под `[a-z0-9_-]{3,64}` и совпадать с именем папки или zip, под которым пак
установлен.

Пакеты SDK, пока они не опубликованы, подключаются как `file:`-зависимости из дерева fv-ui;
`npm run build` в `web/` должен быть выполнен хотя бы раз. См. [JS SDK](/en/fv-ui/sdk) (EN).

## 2. Верстать в браузере

```sh
npm run dev
```

`window.fvui` существует только в игре, поэтому `@fvui/sdk` при импорте ставит мок моста, и
страница получает тестовое состояние титула, миры и серверы. Событие `mode` тоже шлёт игра, так
что вне её экран выбирается адресом:

```txt
http://localhost:5173/?demo=title
http://localhost:5173/?demo=loading
http://localhost:5173/?demo=skin
http://localhost:5173/?demo=skin&layout=mirror
```

`?theme=theme.css` подключает тему пака так, как это сделала бы игра. Мок пишет каждый вызов моста
в консоль — это самый быстрый способ увидеть, как ведутся подписки.

## 3. Собрать

```sh
npm run build
```

`publicDir: 'pack'` кладёт манифест и тему рядом с собранной страницей, так что `dist/` — готовый
пак: `fvui.pack.json`, `index.html`, `theme.css` и `assets/`. `npm run typecheck` запускается
отдельно: сборка Vite типы не проверяет.

## 4. Проверить в игре

Из `mods/`:

```sh
./gradlew :menu:runClient -PdevPack=templates/vue/dist
```

`-PdevPack` важнее, чем `fvui/packs.json`, и принимает абсолютный путь или путь от корня
репозитория. Пока игра запущена, <kbd>F6</kbd> перечитывает все манифесты и перезагружает текущий
экран. `npm run build`, затем F6 — это и есть цикл автора: без перезапуска и без второго движка.

`quit` — право уровня ask, поэтому первое нажатие вызывает экран согласия, а не выход из игры.
Ответьте один раз вручную или заранее разрешите его в `grants` файла `<gamedir>/fvui/packs.json`.

Есть и способ дешевле игры: отрендерить страницу настоящим движком без Minecraft в один PNG.
Он описан в [Dev workflow](/en/fv-ui/dev-workflow) (EN). Именно там всплывают проблемы фреймворков:
всё из [матрицы Servo](/en/fv-ui/servo) нормально собирается, а потом ничего не рисует.

## 5. Отдать игрокам

```sh
npm run pack
```

Команда упаковывает `dist/` в zip с манифестом в корне. Подходит любой вариант:

```txt
<gamedir>/fvui/packs/<id>.zip     распаковывается один раз на сборку в .fvui/cache/packs/
<gamedir>/fvui/packs/<id>/        пак-папка, имя должно совпадать с id манифеста
```

Что ещё класть в zip, где живут данные пака и что с ними делает обновление модпака — в главе
[Distribution](/en/fv-ui/distribution) (EN).

## Три вещи про скины экранов

Их не видно ни на титуле, ни в хабе настроек, но на них спотыкается каждый шаблон:

- раскладку выбирает игра, а не пак. Экраны настроек, которые она понимает целиком, приходят как
  `flow`, всё остальное — как `mirror`. Пак, который умеет только `mirror`, нарисует `flow`-экран
  по координатам, которые игра не заполняла.
- в `flow` у строк списка намеренно нет пригодных границ: раскладка — это то, что игра передаёт
  странице.
- в `mirror` виджет с `clip` — это строка списка с таким id, и место ему внутри блока этого списка.

Полная модель виджетов: [Title, skins, flow and mirror](/en/fv-menu/surfaces) (EN).
