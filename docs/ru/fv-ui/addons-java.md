# Java-аддоны

Аддон — это обычный клиентский мод NeoForge, который регистрирует темы и действия из своего конструктора.
fvui нигде его не называет, и ни одна страница не обязана идти с ним в комплекте: любой пак может читать то, что он зарегистрировал.

`templates/addon-java/` — законченный пример: сборка Gradle, мод и страница пака. Скопируйте его.

## Сборка

fv-ui — зависимость `compileOnly`, её никогда не упаковывают в jar аддона:

```txt
dependencies {
    compileOnly files('fv-ui-0.1.0.jar')
}
```

Те же версии Minecraft, NeoForge и Java, что у самого fvui: 1.21.1, 21.1.250, Java 21, ModDevGradle
2.0.147.

`neoforge.mods.toml` зависит от fvui:

```json
[[dependencies.fvexample]]
modId = "fvui"
type = "required"
versionRange = "[0.1,)"
ordering = "AFTER"
side = "CLIENT"
```

Добавьте вторую, необязательную зависимость от `fvmenu` с `ordering = "BEFORE"`, если аддон регистрирует права
уровня ask. fvmenu проверяет все манифесты паков в собственном конструкторе, а манифест может
перечислять только те права, которые к этому моменту уже объявлены.

## API

```java
FvUiApi.topic(String id, Producer producer)                     // sampled per client tick
FvUiApi.push(String id, Object value)                           // event driven, pushed by the owner
FvUiApi.action(String id, Action handler)                       // ask tier, prompt shows the raw id
FvUiApi.action(String id, Action handler, Tier tier, String about)
FvUiApi.caller()                                                // the calling view, inside an action only
FvUiApi.events(String id)                                       // an ordered event channel
FvUiApi.events(String id, Events.Hook hook)                     // the same, hooked only while listened to
```

Давайте каждому id пространство имён. `example.counter` и `example.ping`, а не `counter` и `ping`: пространство id
плоское и общее с ядром.

## Темы

`Producer` опрашивается раз в клиентский тик и только пока подписана хотя бы одна страница.
`start` выполняется на первом подписчике, `stop` — на последнем, так что неиспользуемая тема ничего не стоит.

```java
FvUiApi.topic("example.counter", new Producer() {
    @Override
    public Object sample() {
        return ++ticks;
    }

    @Override
    public void start() {
        ticks = 0;
    }
});
```

Правила:

- значения сравниваются через `equals` с тем, что каждому виду отправляли в последний раз. Поставщик, который строит
  изменяемую map или список, должен каждый раз возвращать свежую копию, иначе сравнение никогда не сработает.
- опрос идёт внутри насоса движка, посреди кадра. Никогда не открывайте экран, не останавливайте
  движок и не запускайте перезагрузку из `sample`, `start` или `stop`. Ставьте это в очередь через `Minecraft.tell`.
- поставщик, бросивший исключение, пишется в лог раз в тик, а тема становится null. Остальным он
  тик не ломает.
- возвращайте `null`, когда «сейчас ничего нет»; страница сохранит последнее значение.

Данные, которые появляются по событию, вместо этого отправляет (push) их владелец:

```java
FvUiApi.push("example.pings", pings);
```

Отправьте значение один раз из конструктора, чтобы засеять его: тогда уже первый `state.sub` страницы
ответит чем-то, а не ничем.

Используйте `push` для всего, что читает страница загрузки: тиковые темы не работают во время загрузки модов —
шина событий игры ещё не запущена.

## Действия

```java
FvUiApi.action("example.read", args -> ticks, Capabilities.Tier.ALWAYS, "Read the example counter");
```

`args` — это `JsonObject` из Gson, никогда не null. Возвращаемое значение сериализуется Gson и становится
значением, с которым разрешается `fvui.call('act', ...)`. `CompletableFuture` допустим и разрешается в
потоке рендера.

Ошибки: бросайте `BridgeError(code, message)`, чтобы дать странице код, по которому она может ветвиться; всё остальное
доходит до неё как `{code: "error"}`. Действуют те же правила кадра, что и для поставщика, — поэтому действие `quit`
ставит остановку в очередь через `Minecraft.tell`, а не вызывает её на месте.

`FvUiApi.caller()` — вид, чей вызов сейчас обрабатывается, для проверки, которая зависит от
аргументов. `caller().source()` — id пака, стоящего за ним.

## События

Тема — это «побеждает последнее значение» со склейкой; событие — это каждое срабатывание, по порядку. Объявите канал
и запускайте его:

```java
Events.Channel damage = FvUiApi.events("example.hit", () -> attachMyGameListener());
damage.fire(Map.of("amount", 3));
```

Хук выполняется, когда начинает слушать первая страница, а `stop()` — когда уходит последняя, так что канал, который никто
не читает, стоит одной записи в map и ни одного колбэка игры. `fire` на канале, который никто не слушает, ничего не делает
и ничего не ставит в очередь, точно как событие игры; проверяйте `live()`, прежде чем строить дорогие
данные. Страница подписывается через `events.sub` и читает через `fvui.on`, см. [Темы и действия](/ru/fv-ui/topics-actions).

Каждая тема уже является событием под именем `topic:<id>`, так что не добавляйте канал, который говорит только «эта
тема изменилась».

## Уровни и строка согласия

Всё, что регистрирует мод, по умолчанию — право уровня ask, так что пак не может до него добраться, пока
игрок не скажет «да». Перегрузка `action` с четырьмя аргументами задаёт уровень и предложение, которое показывает
экран согласия:

```java
FvUiApi.action("example.ping", ExampleAddon::ping, Capabilities.Tier.ASK,
    "Show a message from the example addon");
```

| уровень | для чего |
|---|---|
| `ALWAYS` | чтение состояния, всё, что остаётся внутри игры и собственных данных пака |
| `ASK` | всё, что выходит к игроку, в мир, в файловую систему или в сеть |

Объявление уровня — это ещё и то, что позволяет указать id в манифесте пака: необъявленный id не проходит
проверку манифеста с «unknown capability», а id, которого нет в манифесте, отклоняется
без запроса. Со стороны страницы оба случая молчаливы, если не считать строки в логе и
отказа `{code: "capability"}`, так что объявляйте до того, как сконструируется fvmenu.

Id ядра остаются во владении ядра. Объявление `quit` из мода игнорируется со строкой warn, так что ни один аддон не может
расширить или переформулировать то, что разрешает сам fvui.

После этого запрос выглядит так:

```txt
Example Addon Pack (fvexample) wants to:
Show a message from the example addon
example.ping
```

## Сторона страницы

Ничего особенного. Темы другого мода читаются как темы ядра, а его действия идут через тот же
вызов `act`:

```js
fvui.call('state.sub', { topics: ['example.counter'] });
fvui.state('example.counter', (value) => console.log(value));
await fvui.call('act', { id: 'example.ping', args: { text: 'Hello' } });
```

Манифест пака перечисляет те, что уровня ask:

```txt
"capabilities": ["state.sub", "example.ping"]
```

## Распространение

Jar мода кладётся в `mods/` рядом с fv-ui и fv-menu. Страница — обычный UI-пак, так что она кладётся
в `<gamedir>/fvui/packs/<id>/`, в папку с именем в точности как `id` в манифесте. Остальное —
в главе [Распространение](/ru/fv-ui/distribution).

Аддон, у которого страница необязательна, — это нормально: зарегистрируйте темы и дайте автору пака ими пользоваться.

## Аддоны для HUD

У `fvhud` свой WebView и, значит, свой активный пак, поэтому HUD-аддон регистрирует темы и
действия точно так же, как этот, а пак несёт для экрана `hud`, а не для меню. Ничто
в этой главе для него не меняется. Сам экран — в главе [Экран HUD](/ru/fv-hud/hud-surface): темы, которыми fvhud уже владеет,
вызов островов `hud.rects` и файл слоёв.

Моду, которому нужна только своя полоска на HUD, пак вообще не нужен: зарегистрируйте GUI-слой
обычным способом, и он продолжит рисоваться, потому что fvhud отменяет только те id `minecraft:`, которые называет сам.

## Серверные аддоны

`FvUiApi` — клиентский реестр: он работает в потоке рендера, и выделенный сервер до него никогда
не доходит. Серверная половина — `FvUiServerApi` в `fatevis.fvui.common`; он компилируется на обеих сторонах и
ничего не делает там, где нет канала, так что один jar аддона может регистрировать оба.

```txt
FvUiServerApi.topic("shop.balance", 40, () -> economy.total());
FvUiServerApi.action("shop.buy", (player, args) -> shop.buy(player, args), Commands.LEVEL_ALL, "Buy");
```

Страница читает это с префиксом `server.data.`, здесь — как `server.data.shop.balance`, и вызывает через `server.act`. Каждому id действия
нужен уровень команд, а паку нужно право `server:data`, прежде чем он сможет тронуть то или другое.
Вся серверная сторона — в главе [Серверы](/ru/fv-ui/server): канал, лимиты, `/fvui` и паки, которые присылает сервер.
