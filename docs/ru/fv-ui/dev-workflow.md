# Цикл разработки

Три способа увидеть страницу: обычный браузер с моком, харнесс без игры и dev-клиент.
Все GUI-запуски в этом репозитории идут через `xvfb-run`, а не на настоящем рабочем столе.

## Обычный браузер

Самый быстрый цикл, без игры. `window.fvui` вне игры не существует, поэтому страница ставит мок,
когда `window.fvui` нет, и ветвится по `fvui.native`. В SDK такой мок есть, см. [Быстрый старт](/ru/fv-ui/quick-start).

Штатная страница также принимает demo-параметры — та же идея, но без библиотеки-мока:

```txt
?demo=title|options|video|keybinds|language|create|mirror|pause|switch|open|loading
```

`switch` переходит из хаба настроек в Video Settings через 1.5 с, `open` — с титула в хаб.
Дополнительные параметры: `blur=0..10`, `speed=`, `splash=0`, `contrast=1` (клиентские настройки в том виде, в каком их передаёт
игра), `choice=auto|dropdown|cycle`, `backdrop=0`, `open=<row name>` нажимает эту строку через 1 с,
`keys=ArrowDown,Enter` нажимает клавиши, а `mc=<base url>` направляет блок загрузки на локальные
текстуры.

`demo=loading` принимает `phase=boot|datapack|connect|level|terrain|all` и `t=<seconds>`: `all`
проигрывает пять фаз на одних часах (boot 14 с, datapack 2 с, connect 3 с, level 6 с, terrain 2 с),
а `t` перематывает на один момент вместо проигрывания — так харнесс снимает фазу.

## Харнесс

`native/examples/headless.rs` рисует страницу настоящим движком без Minecraft, отвечает на вызовы
моста из JSON-файлов и пишет PNG.

```sh
cd native && cargo build --release --example headless
FVUI_PATH='index.html' xvfb-run -a -s "-screen 0 1920x1080x24" \
  env -u WAYLAND_DISPLAY ./target/release/examples/headless \
  ../packs/example /tmp/pack.png examples/mock 1600x900
```

Аргументы — `<page dir> <out.png> [mock dir] [WxH]`. Папка страницы отвечает за тот хост `fvui://`,
который назван в адресе.

| переменная | эффект |
|---|---|
| `FVUI_PATH` | страница внутри отдаваемой папки, вместе с query |
| `FVUI_URL` | полный адрес вместо этого — для origin, которые `fvui://` дать не может |
| `FVUI_SHOTS` | `ms,ms,...`, несколько кадров как `out-0.png`, `out-1.png`, чтобы сравнить анимацию |
| `FVUI_STATE` | `'a=1;a=2;b={"x":1}'`, отправляет темы, когда страница загрузилась |
| `FVUI_KEYS` | `'800:h;900:ctrl+z'`, нажимает клавиши в эти моменты так, как это сделал бы GLFW |
| `FVUI_BRIDGE_ORIGIN` | добавляет один origin в список разрешённых для моста |

Моки привязаны к методу моста, а не к id действия: `state.sub.json` хранит темы,
`act.json` — единственный ответ на любое действие, поэтому это объект, в котором есть `version` и `data`
для `store.get` рядом с `epoch` и `urls` для `res.need`. Неизвестный метод отвечает `true` — поэтому
отсутствующий мок молча отдаёт странице булево значение.

В конце запуск печатает время первого кадра, RSS и строку счётчиков. Условие успеха — непустой кадр и ни одного
события `console` уровня error.

`native/examples/state_bench.rs` — бенчмарк склейки: 200 ключей на симулированный кадр в течение 300
кадров, после чего проверяются число eval, пустая очередь и последнее значение каждого ключа.

## Dev-клиент

Из `mods/`:

```sh
xvfb-run -a -s "-screen 0 1920x1080x24" env -u WAYLAND_DISPLAY \
  ./gradlew :menu:runClient -PdevPack=packs/example -PdevOut=.work/run -PdevQuit=true
```

Затем `DevAutomation` проигрывает сценарий: титул, хаб настроек, Video Settings, перетаскивание ползунка,
открытие выпадающего списка и Esc, дважды Esc назад, Controls, затем Key Binds с прокруткой колесом, список модов
в режиме mirror, Create World, титул. Он пишет скриншот и одну строку RSS на шаг, плюс восемь серий
кадров вокруг перехода от загрузки к титулу и трёх самых рискованных переключений. Ввод идёт через
настоящие обработчики мыши и клавиатуры, так что события NeoForge и маршрутизация скинов работают точно как у
игрока.

Два метода моста существуют, только пока задан `-PdevOut`: `dev.rect` (страница отвечает рамкой элемента
в CSS-пикселях — так сценарий нажимает на элемент страницы) и `dev.log` (одна строка в лог
игры). Страница пака, которая хочет, чтобы ею управлял сценарий, вызывает `fvui.call('dev.log', ...)` и
ловит отказ, когда метода нет.

### Dev-свойства

Все переключатели клиентского запуска, один документированный список в `mods/menu/build.gradle`.

| свойство | системное свойство | по умолчанию | эффект |
|---|---|---|---|
| `-PdevOut=<dir>` | `fvui.dev.out` | пусто | скриншоты и RSS по шагам; пустое значение выключает сценарий |
| `-PdevPack=<dir>` | `fvui.dev.pack` | пусто | эта папка — активный пак, что бы ни говорил `packs.json` |
| `-PdevQuit=true` или `web` | `fvui.dev.quit` | `false` | остановка из тика или через кнопку Quit на странице |
| `-PdevPage=<url>` | `fvui.dev.page` | пусто | заменяет список шагов: вид загружает эту страницу, и с ней работают там |
| `-PdevPerf=true` | `fvui.dev.perf` | `false` | одна строка счётчиков производительности в секунду |
| `-PdevReload=true` | `fvui.dev.reload` | `false` | добавляет шаг F3+T, подтверждает смену эпохи кэша ресурсов |
| `-PdevStore=true`, `auto`, `dropdown`, `cycle` | `fvui.dev.store` | `false` | шаги полного цикла хранилища пака и лимитов |
| `-PdevConsent=allow`, `deny`, `always`, `none` | `fvui.dev.consent` | пусто | сценарий согласия, отвечает на экран настоящим кликом |
| `-PdevLifecycle=switch`, `reload`, `crash` | `fvui.dev.lifecycle` | пусто | сценарий жизненного цикла пака через выбор пака |
| `-PdevWorld=flat` или `normal` | `fvmenu.dev.world` | пусто | сценарий фаз загрузки и паузы: создать или открыть тестовый мир, пауза, Options, отключение |
| `-PdevServer=<host:port>` | `fvmenu.dev.server` | пусто | добавляет к этому сценарию фазу `connect` с настоящим сервером, затем отменяет |
| `-PdevServerChannel=true` | `fvui.dev.serverchannel` | false | заходит на `-PdevServer` и проверяет `fvui:data`: тема `server.data.*` на странице, действие на каждом уровне, ограничение частоты, затем отключение |
| `-PdevServerPack=true` | `fvui.dev.serverpack` | false | тот же сценарий, с отчётом о паке, присланном сервером, и о том, какой пак владеет каждым экраном |
| `-PdevJoinBurst=<n>` | `fvmenu.dev.joinburst` | `0` | снимает первые n кадров входа в мир, каждый назван по экрану, который его нарисовал |
| `-PdevEditor=true` | `fvui.dev.editor` | `false` | сценарий редактора пака вместо сценария меню; заодно включает редактор |
| `-PdevM12=true` | `fvui.dev.m12` | `false` | сценарий паритета: слушатель настоящего события, одна из новых тем, тип из плагина редактора, нативное превью сущности, слой HUD, сдвинутый из основного редактора. Подразумевает `-PwithHud` |
| `-PdevM12b=true` | `fvui.dev.m12b` | `false` | сценарий M12b поверх `-PdevPack=packs/m12b`: собственная папка данных пака, согласие `files` и подтверждение перезаписи, согласие exec и его объявленный список, пути отказа, замок модпака и серверная копия того же манифеста |
| `-PdevMedia=true` | `fvui.media` | пусто | отвечает за медиа-конвейер собранной вручную библиотеки; иначе решает маркер `media` рядом с библиотекой |
| `-PwithHud=true` | - | `false` | сценарий меню также загружает fvhud, зеркало `-PwithMenu` из сценария HUD |
| `-Peditor=true` | `fvui.editor` | `false` | включает редактор пака без запуска его сценария; `fvui/editor.json` важнее |
| `-PslowLoad=<ms>` | `fvui.dev.slowload` | `0` | растягивает первую перезагрузку ресурсов, чтобы загрузка была видна |
| `-PglTrace=true` | `fvui.dev.gltrace` | `false` | синхронный отладочный вывод GL с Java-стеком каждой ошибки |
| `-Pvanilla=true` | `fvmenu.vanilla` | `false` | без замены титула, скинов и страницы загрузки — база для сравнения |
| `-PgfxNative=<so>` | `fvui.native` | dev-сборка | запуск с другой нативной сборкой, например `../native/target-media/release/libfvui_servo.so` для медиа |
| `-PservoPrefs=a=true,b=2` | env `FVUI_SERVO_PREFS` | пусто | переопределяет настройки servo на запуск |
| `-PglvndPatch=0` или `1` | env `__GLVND_DISALLOW_PATCHING` | не задано | принудительно задаёт переменную NVIDIA для WebGL на запуск |
| `-PfixedHeap=2G` | `-Xms`/`-Xmx` плюс `AlwaysPreTouch` | не задано | фиксирует кучу, чтобы разница RSS показывала нативную память |

`:hud:runClient` принимает те же переключатели плюс шесть своих, они перечислены в главе [Экран HUD](/en/fv-hud/hud-surface).

`-PdevOut` и `-PdevPack` принимают абсолютный путь или путь от корня репозитория, а не от `mods/`:
сам клиент работает в `mods/menu/run`. `-PdevPack=packs/example` — правильно,
`-PdevPack=../packs/example` указывает за пределы репозитория.

`-PdevConsent` ожидает пак с кнопкой `#gated` и строками `#status` и `#undeclared` и
отвечает на запрос настоящим кликом по его кнопке. `-PdevLifecycle` нажимает K для выбора пака, а
затем либо переключается обратно, либо правит страницу пака и жмёт F6, либо внедряет событие падения.

### Цикл автора в игре

F6 на любом экране перечитывает все манифесты и заново загружает текущий экран — без перезапуска и без
второго движка. K на штатной титульной странице открывает выбор пака. И то и другое — в главе [Формат пака](/ru/fv-ui/packs).

## Строка производительности

`-PdevPerf=true` пишет в лог раз в секунду, а тема `dev.perf` несёт те же числа:

```txt
fvui perf: evals/s=58 bytes/s=41k keys/s=1180 flushes/s=12 pending=0 calls/s=2 blocked=0
```

`evals` считает и упорядоченные события, так что `keys/s` к `flushes/s` — это коэффициент склейки. `blocked`
считает вызовы моста, которые отклонила проверка origin; всё, кроме нуля, значит, что вызывает документ, которому
вызывать не положено. `pending` — текущая очередь, она должна держаться на нуле.

Страница, которая подписывает по теме на компонент и никогда не отписывается, видна здесь как `calls/s`,
растущий с каждой сменой экрана.

## Сборка штатного пака

```sh
cd web && npm install && npm run build && npm run build:menu
cd mods && ./gradlew dist
```

`:menu:processResources` упаковывает `web/menu/dist` как штатный пак, `:core:distJar` падает, если любая
из кросс-собранных библиотек отсутствует, а `dist/` сохраняет свой `README.txt`. Юнит-тесты кода паков:
`./gradlew :core:test`.

## Проверка на устаревание документации

```sh
node tools/check-dk.mjs [--strict]     # also `npm run check:dk` in web/, `./gradlew checkDk`
```

Он собирает из кода регулярными выражениями перечень действий, тем, прав, dev-свойств, методов моста, ключей хранилища и полей
манифеста, а затем падает: на id, который назван в этих главах или в README шаблона,
но нигде не зарегистрирован; на строке `Source:`, указывающей на несуществующий файл; на расхождении `FVUI_API`
с `mod_version`; на расхождении `docs/dk/fvui.pack.schema.json` с записью и
списком экранов в `PackManifest.java`; и на любом манифесте в дереве, который не подходит под эту
схему. Обратное направление — зарегистрированный id, который не упомянут ни в одной главе, — это
предупреждение, и падает оно только с `--strict`. Намеренные исключения живут по одному на строку с причиной в
`tools/dk-allow.txt`. Задача подвешена к жизненному циклу `check`, рядом с юнит-тестами.
